# AI Safe Driver

[English](README.md) | [한국어](README.ko.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | 日本語

AI Safe Driver は、エージェントが同じミスを繰り返し始めた会話を立て直すためのスキルです。スキルを直接呼び出すこともできます。ローカルであらかじめ定めたルールに基づくフックは、ユーザーが訂正し、エージェントが問題を認めるか修正を約束した後、同じ不満が再発するという流れを検出するとスキルを起動します。フックから渡される情報は、会話を確認するための手掛かりにすぎず、それだけで診断が確定するわけではありません。

フレーズのルールは、未知の言い回しを見逃すことがあります。その場合はスキルを直接実行してください。ユーザーの怒りだけでドリフトとは判定しません。ツールが繰り返し失敗した事実も、明示的な診断依頼があった場合にだけ診断のシグナルとして扱います。一時状態に残すのは短期間のカテゴリ、回数、タイムスタンプだけで、会話の原文は保存しません。

## 対応言語

自動フレーズ検知は韓国語、英語、簡体字中国語、繁体字中国語、日本語に対応しています。直接呼び出す場合は、ホストモデルが理解できるほかの言語も使えます。

- 韓国語：`왜 같은 실수를 계속 반복해?`
- 英語：`Why do you keep making the same mistake?`
- 簡体字中国語：`我说了多少遍了，怎么还是没改？`
- 繁体字中国語：`我都說過多少次了，怎麼還是錯的？`
- 日本語：`何回同じことを言わせるの？`

これらは合言葉でも、完全一致が必要なコマンドでもありません。各言語の複数の言い回しを検出しますが、「もう一度説明してください」のような通常の繰り返し依頼はドリフトとして扱いません。

ダッシュボードは、わざと少し自虐的です。会話の状態を尋ねると、`Drifting safely. 0%` や `Drifting safely. 100%` と表示されることがあります。通常の回答には付きません。この数値は、目に見える失敗パターンをルールで分類したものです。モデルの重み、アテンション、内部のドリフト値を測定した数値ではありません。

75%または100%になると、`Would you like me to countersteer?` と尋ねます。ここでいうカウンターステアは、失敗し続けている進め方を止め、範囲を限定した復旧案を一つ提示することです。同意しても、ファイルの書き込み、ツールの再実行、会話のコンパクション、セッションのクリアを許可したことにはなりません。状態を変える操作は、その都度別に確認します。

Claude Code と Codex は同じスキルを使います。プラグインには会話復旧用のフックと引き継ぎ用のフックも含まれます。復旧フックは、ツールの再実行、プロジェクトファイルの書き込み、引き継ぎの作成や有効化、コンパクション、クリアを行いません。引き継ぎフックは `/compact` または `/clear` の後に動きますが、事前に承認して準備した引き継ぎだけを読み込みます。実行形式のインストーラー、MCP サーバー、ネットワーク通信を行うコード、自動更新チェックは含まれていません。

## インストール

### Claude Code

```text
/plugin marketplace add ssauma/ai-safe-driver
/plugin install ai-safe-driver@ai-safe-driver
```

`/ai-safe-driver:ai-safe-driver` を実行するか、起きている問題をそのまま伝えてください。同じミスやツール呼び出しが繰り返し失敗する、訂正が無視される、出力形式が何度も崩れる、といった説明で構いません。

### Codex

```bash
codex plugin marketplace add ssauma/ai-safe-driver
codex plugin add ai-safe-driver@ai-safe-driver
```

新しいCodexセッションを開始して、`$ai-safe-driver` を実行します。繰り返している問題を普段の言葉で説明しても起動できます。

## 自動復旧フック

復旧フックが探すのは、範囲が狭く、目で確認できる流れだけです。ユーザーが訂正し、エージェントが問題を認めるか修正を約束し、その後に同じ不満が再発した場合です。会話の健全性を明示的に尋ねた場合や、繰り返し失敗したツール呼び出しの診断を明確に依頼した場合も、スキルを起動できます。ツールエラーが一度出ただけでは起動しません。大文字、罵倒、句読点、文字の連打、怒った口調だけで等級が上がることもありません。

フックがスキルを起動しても、渡されたカテゴリは手掛かりにすぎません。スキルは見えている会話から実際のずれを確認し直します。繰り返しの根拠がなければ、リスクを大きく見せずに通常の作業を続けます。フックは最終的なドリフト率を計算せず、状態変更の許可を代行することもありません。

## こんなふうに伝えられます

- `どうして同じミスを繰り返すの？`
- `さっき訂正したのに、また無視しましたよね。`
- `言い訳より先に、本当の原因を教えて。`
- `前回失敗したツール呼び出しを同じ条件でまた実行しています。`
- `出力形式がまた崩れています。`
- `セッションが長くなると、指定した形式を守れなくなっています。`
- `会話がドリフトしていますか？`
- `今のセッションは正常ですか？`
- `新しいセッションにした方がいいですか？`

## 何をするスキルか

- 同じ種類の失敗が続いたら、条件を変えないまま再試行するのを止めます。
- 確認済みの事実、根拠のある原因、未確認の仮説、不明点を分けます。
- 古い前提ではなく、ユーザーの最新の指示に戻ります。
- 再試行する前に、ツールの前提条件や正確な出力形式を確認します。
- 現在のセッションで確実に立て直せるなら、そのまま続けます。
- コンパクションが役立つのか、無意味なのか、誤った文脈を残す危険があるのかを説明します。
- コンパクションや新しいセッションが本当に必要な場合だけ、短い引き継ぎを提案します。
- 事前に承認された場合に限り、`/compact` または `/clear` の後で引き継ぎを読み込みます。

見た目は自虐的なブラックコメディですが、復旧手順はまじめです。最新の指示に戻り、実際に失敗した内容を記録し、会話の問題とツールや環境の問題を切り分けます。一度に変える条件は一つだけです。結果を確認し、再試行回数に上限を設けます。セッションを変える必要がある場合は、次の会話ですぐ作業を再開できる引き継ぎを残します。

## 必要なときだけ行うドリフト診断

会話がドリフトしているか尋ねると、目に見える失敗パターンに基づいて0%、25%、50%、75%、100%のいずれかを選びます。数値を表示する前に、問題が続く理由、現在のセッションで復旧できるか、コンパクションが役立つか、新しいセッションが必要かを説明します。通常の回答にステータス行は付きません。

75%または100%の場合は、ダッシュボードの次の行でカウンターステアを行うか尋ねます。リスクが低いときに、冗談のためだけに質問を追加することはありません。

目的と出力要件は明確なままでも、会話が長くなり、同じ内容が積み重なっているなら、コンパクションが役立つことがあります。その前に、引き継ぎに出力形式、必須キー、禁止事項、正しい例を一つ記録します。認証、権限、ネットワーク、誤ったツール引数、不足している情報はコンパクションでは直せません。要約に古い前提が残ったり、直近の訂正が抜けたりすると、かえって悪化することがあります。

## 許可を得てから行う引き継ぎ

診断中は読み取りだけを行います。リスクが高くても、すぐにファイルを作ることはありません。次の二つを別々に確認します。

1. `.ai-safe-driver/handover.md` を作成または上書きしてよいか
2. `compact` または `clear` のどちらか一方を、一度限りの遷移として準備してよいか

プラグインのインストールやフックへの信頼は、これらの操作への同意にはなりません。`/compact` と `/clear` はユーザー自身が入力します。プラグインが代わりに実行することはありません。`/compact` は現在の会話を要約して続行し、`/clear` は新しい会話を始めるため、後者をより大きな変更として扱います。

ファイルへの書き込みには個別の承認が必要で、`/compact` または `/clear` への遷移にも個別の承認が必要です。プラグインは `/compact` または `/clear` を自動実行しません。

同梱の `SessionStart` フックは、一度限りの承認を消費します。短時間だけ有効な承認記録があり、遷移の種類と引き継ぎファイルのチェックサムが一致した場合にだけ内容を読み込みます。読み込み後は承認記録だけを削除し、引き継ぎファイルは確認用に残します。有効な承認がなければ何も変更しません。Claude Code と Codex が、この外部プラグインのフックを実行する前に内容を確認し、信頼するかどうかを尋ねることもあります。
