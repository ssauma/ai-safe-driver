# AI Safe Driver

[English](README.md) | [한국어](README.ko.md) | 简体中文 | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md)

> **正在安全漂移。100%**
>
> 好消息：检测器工作正常。坏消息：它确实有东西可检测。

AI Safe Driver 用来处理智能体反复犯同一个错误的对话。你可以直接调用这个技能。本地确定性钩子也会留意一种明确的顺序：用户先纠正，智能体承认错误或答应修复，随后同类问题再次出现。钩子只提醒技能检查当前对话，不会直接下结论。

短语规则可能漏掉没见过的说法，因此随时都可以直接运行技能。生气不代表发生了漂移。观察到工具反复失败后，也只有收到明确的诊断请求才会把它当作信号。临时状态只在短期内保留类别、次数和时间戳，不会保存对话原文。

## 支持的语言

自动短语检测支持韩语、英语、简体中文、繁体中文、日语。直接调用时，也可以使用运行这项技能的模型能够理解的其他语言。

- 韩语：`왜 같은 실수를 계속 반복해?`
- 英语：`Why do you keep making the same mistake?`
- 简体中文：`我说了多少遍了，怎么还是没改？`
- 繁体中文：`我都說過多少次了，怎麼還是錯的？`
- 日语：`何回同じことを言わせるの？`

这些句子不是口令，也不必一字不差。钩子能识别各语言中的多种抱怨方式，但“请再解释一次”这类普通的重复请求不会被当成漂移。

仪表盘故意带一点自嘲，但风险为零时不会声称正在漂移。你主动询问对话状态时，技能可能显示 `No current signs of drift.` 或 `Drifting safely. 100%`。普通回复不会附带这行文字。百分比是根据可见失败模式得出的规则等级，不是对模型权重、注意力或某种内部漂移数值的测量。

结果为 75% 或 100% 时，技能会问 `Would you like me to countersteer?`。这里的“反打方向盘”是指停止当前失败方式，再提出一个范围明确的恢复方案。回答同意只表示愿意讨论这个方案，并不授权插件写文件、重试工具、压缩对话或清空会话。每项状态变更都需要单独确认。

Claude Code 和 Codex 使用同一份技能。插件还带有对话恢复钩子和交接钩子。恢复钩子不会重试工具、写入项目文件、创建或启用交接文档，也不会压缩或清空会话。交接钩子会在 `/compact` 或 `/clear` 之后运行，但只会载入你事先批准并准备好的交接内容。插件不含可执行安装程序、MCP 服务器、联网代码或自动更新检查。

## 安装

### Claude Code

```text
/plugin marketplace add ssauma/ai-safe-driver
/plugin install ai-safe-driver@ai-safe-driver
```

运行 `/ai-safe-driver:ai-safe-driver`，或者直接说明发生了什么，例如同一个错误或工具调用不断失败、纠正被忽略、输出格式一再出错。

### Codex

```bash
codex plugin marketplace add ssauma/ai-safe-driver
codex plugin add ai-safe-driver@ai-safe-driver
```

可以直接运行 `$ai-safe-driver`。也可以用自己的话描述反复出现的问题。在新会话中，请简要说明反复发生的失败或提供已批准的交接文件；此技能无法读取不可见的先前对话。

## 自动恢复钩子

自动钩子需要 Node.js 20 或更高版本。

恢复钩子只检查范围很窄、能够直接观察到的顺序：用户纠正问题，智能体承认错误或承诺修复，随后同类抱怨再次出现。明确的对话健康检查，或明确要求诊断反复失败的工具调用，也可以唤醒技能。单次原始工具错误不够。大写、脏话、标点、重复字符和愤怒语气本身都不会提高等级。

钩子唤醒技能时，所附类别只是一条线索。技能必须回到当前可见对话，重新确认实际偏差。如果看不到重复证据，就不会夸大风险，而是继续正常工作。钩子不计算最终漂移百分比，也不替用户批准任何状态变更。

## 可以这样说

- `为什么总犯同一个错误？`
- `我刚纠正过，你怎么又忽略了？`
- `别急着道歉，先告诉我真正原因。`
- `又重复了上次失败的工具调用。`
- `输出格式怎么又错了？`
- `会话太长以后，你一直守不住指定格式。`
- `对话是不是跑偏了？`
- `现在的会话状态正常吗？`
- `要不要开一个新会话？`

## 它会做什么

- 同类失败反复出现时，停止原样重试。
- 分开记录已确认事实、有依据的原因、待验证假设和未知项。
- 回到用户最新指令，不再沿用已经失效的旧假设。
- 再次操作前，先核对工具条件或精确的输出格式。
- 如果当前会话能够可靠恢复，就留在当前会话继续。
- 说明压缩上下文是否有帮助、是否无效，或是否可能保留错误前提。
- 只有确实需要压缩或新会话时，才建议制作简短交接文档。
- 只有得到事先批准，才会在 `/compact` 或 `/clear` 后重新载入交接内容。

外表是自嘲式黑色幽默，内部采用严谨的故障恢复流程：回到最新指令，记录实际失败，把对话问题和工具或环境问题分开，每次只改变一个条件，然后验证结果并限制重试次数。如果必须换会话，则留下足够下一次继续工作的交接内容。

## 按需漂移检查

你询问对话是否漂移时，技能会根据可见失败模式选择 0%、25%、50%、75% 或 100%。显示数字前，它会先说明问题为什么持续、当前会话能否恢复、压缩是否有用，以及是否应该开始新会话。普通回复不会显示状态行。

结果为 75% 或 100% 时，仪表盘下一行会询问是否要反打方向盘。风险较低时不会为了凑笑话而多问一句。

当目标和输出要求仍然清楚，只是对话过长且内容重复时，压缩可能有帮助。技能会先在交接内容中固定输出格式、必填字段、禁止项和一个正确示例。身份验证、权限、网络、错误的工具参数或缺失事实无法靠压缩解决。如果摘要保留了旧假设，或遗漏了用户最近的纠正，压缩反而可能让问题更严重。

## 只有获得许可才会交接

诊断阶段是只读的。即使风险很高，技能也不会立刻写文件，而是分别询问：

1. 是否可以创建或覆盖 `.ai-safe-driver/handover.md`
2. 是否可以只为 `compact` 或 `clear` 其中一种切换做一次性准备

安装插件或信任钩子不代表同意上述操作。`/compact` 和 `/clear` 仍由你亲自输入，插件不会代为执行。`/compact` 会总结当前对话并继续，`/clear` 会开启新对话，因此后者被视为更大的变更。

写入文件需要单独批准，准备 `/compact` 或 `/clear` 切换也需要单独批准。插件不会自动执行 `/compact` 或 `/clear`。

如果 Git worktree 尚未忽略 `.ai-safe-driver/`，准备交接时还需要把这一行加入该 worktree 的本地 Git 排除文件。技能会先显示准确路径，并在写入前征得许可。它不会修改共享的 `.gitignore` 或 Git 配置。

内置的 `SessionStart` 钩子会消耗一次性批准。只有短期批准记录仍有效，而且切换类型与交接文件的 SHA-256 哈希值都一致时，它才会载入交接内容。载入后只删除批准记录，交接文件会保留供你检查。没有有效批准时，钩子不会做任何更改并静默退出。Claude Code 和 Codex 也可能要求你先检查并信任这个第三方钩子。
