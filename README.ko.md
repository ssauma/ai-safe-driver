# AI Safe Driver

[English](README.md) | 한국어

정상운행중입니다. AI Safe Driver는 에이전트가 같은 실패를 반복할 때 변명부터 늘어놓지 않고, 확인 가능한 원인을 찾은 뒤 현재 작업을 복구하도록 돕습니다. 대화를 안정적으로 복구하기 어려운 경우에만 새 세션을 권장합니다.

일부러 믿음직하지 않게 만든 계기판은 사용자가 물었을 때만 `정상운행중입니다. 드리프트 0%` 또는 `정상운행중입니다. 드리프트 100%`처럼 비유적인 상태를 표시합니다. 모든 답변에 푸터를 붙이지 않으며, 모델의 가중치·어텐션·실제 내부 드리프트 비율을 측정하는 기능도 아닙니다.

위험도가 75% 또는 100%면 `카운터 스티어링 하시겠습니까?`라고 묻습니다. 여기서 카운터 스티어링은 실패하던 경로를 멈추고 제한된 복구 방법 하나를 제안한다는 뜻입니다. 사용자가 동의해도 파일 작성·툴 재시도·컴팩션·초기화까지 자동으로 허락한 것으로 확대하지 않으며, 상태를 바꾸는 작업은 각각 다시 명시적으로 허락받습니다.

Claude Code와 Codex가 하나의 공용 스킬과 승인 기반 핸드오버 훅을 사용합니다. 실행형 설치 프로그램, MCP 서버, 네트워크 코드, 자동 업데이트 검사는 포함하지 않습니다. 훅은 사용자가 일회성 핸드오버를 명시적으로 승인하고 준비하지 않으면 아무 작업도 하지 않습니다.

## 설치

### Claude Code

```text
/plugin marketplace add ssauma/ai-safe-driver
/plugin install ai-safe-driver@ai-safe-driver
```

`/ai-safe-driver:ai-safe-driver`로 직접 실행하거나, 반복된 실수·동일한 툴 호출 실패·무시된 정정·출력 형식 재위반을 자연스럽게 말하면 됩니다.

### Codex

```bash
codex plugin marketplace add ssauma/ai-safe-driver
codex plugin add ai-safe-driver@ai-safe-driver
```

새 Codex 세션에서 `$ai-safe-driver`로 실행하거나 반복된 실패를 평소 말투로 설명하면 됩니다.

## 자동 실행 표현

- `왜 같은 실수를 반복해?`
- `또 내 말을 무시했잖아.`
- `변명하지 말고 원인을 말해.`
- `똑같은 툴 호출을 또 했네.`
- `출력 형식을 또 틀렸잖아.`
- `클로드 세션이 길어지니까 출력 형식을 계속 못 맞추네.`
- `지금 드리프트 난 거야?`
- `정상이냐?`
- `드리프트냐?`
- `지금 상태 어때?`
- `새 세션을 파야 해?`

## 달라지는 행동

- 같은 실패가 반복되면 변경 없는 재시도를 중단
- 관찰된 사실, 직접 원인, 가설, 모르는 점을 분리
- 최신 지시를 다시 확정하고 폐기된 가정을 제거
- 재시도 전에 툴의 선행 조건이나 출력 계약을 검증
- 복구할 수 있으면 현재 세션을 유지
- 컴팩션이 도움이 되는지, 효과가 없는지, 잘못된 상태를 보존할 위험이 있는지 설명
- 컴팩션이나 새 세션이 정말 필요하면 짧은 인계 문서를 제안
- 명시적으로 승인한 경우에만 `/compact` 또는 `/clear` 뒤 인계 문서를 다시 주입

겉모습은 자조적인 블랙코미디지만, 내부는 AI 엔지니어링의 정석을 따릅니다. 최신 계약을 보존하고, 재현 가능한 증거를 남기며, 모델 문맥 문제와 툴·환경 문제를 분리하고, 한 번에 한 조건만 바꾸고, 결과를 기계적으로 검증하며, 재시도 횟수를 제한하고, 필요하면 깨끗한 인계로 전환합니다.

## 요청할 때만 하는 드리프트 점검

사용자가 현재 대화가 정상인지 드리프트 중인지 명시적으로 물으면, 관찰 가능한 실패 신호를 기준으로 0%·25%·50%·75%·100% 중 하나를 표시합니다. 같은 문제가 계속되는 근거 있는 원인, 현재 세션의 복구 가능성, 컴팩션의 도움 여부, 새 세션을 권장하거나 권장하지 않는 이유도 함께 설명합니다. 평범한 답변에는 이 상태 문구를 붙이지 않습니다.

75% 또는 100% 진단은 계기판 다음 줄에서 카운터 스티어링 여부를 묻습니다. 위험도가 낮을 때는 농담을 위해 질문을 덧붙이지 않습니다.

현재 목표와 정확한 출력 계약은 명확하지만 길고 중복된 대화가 판단을 방해할 때는 컴팩션이 도움이 될 수 있습니다. 컴팩션 전 인계에는 요구 형식, 필수 키, 금지 사항, 유효한 예시 하나를 고정합니다. 인증·권한·네트워크·잘못된 툴 인자·누락된 사실은 컴팩션으로 해결되지 않습니다. 요약이 오래된 가정을 보존하거나 사용자의 최신 정정을 누락하면 오히려 드리프트가 심해질 수 있습니다.

## 허락받고 작동하는 핸드오버

진단 자체는 읽기 전용입니다. 위험도가 높아도 바로 파일을 만들지 않고 다음 두 가지를 따로 허락받습니다.

1. `.ai-safe-driver/handover.md`를 새로 만들거나 덮어써도 되는지
2. `compact` 또는 `clear` 중 어느 전환을 일회성으로 준비해도 되는지

플러그인 설치나 훅 신뢰는 위 두 작업의 허락으로 취급하지 않습니다. `/compact`와 `/clear`도 사용자가 직접 입력합니다. 플러그인이 스스로 실행하지 않습니다. `/compact`는 현재 대화를 요약해 이어가고, `/clear`는 새 대화를 시작하므로 더 큰 변경이라고 먼저 설명합니다.

포함된 `SessionStart` 훅은 일회성입니다. 짧은 유효시간을 가진 승인 기록의 전환 종류와 핸드오버 체크섬이 모두 맞을 때만 문서를 다시 읽습니다. 성공하면 승인 기록만 제거하고 핸드오버 문서는 검토용으로 남깁니다. 유효한 승인이 없으면 아무 출력이나 변경 없이 종료합니다. Claude Code와 Codex는 관리형이 아닌 플러그인 훅을 실행하기 전에 사용자가 내용을 검토하고 신뢰하도록 요구합니다.
