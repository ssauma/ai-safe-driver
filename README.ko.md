# AI Safe Driver

[English](README.md) | 한국어 | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md)

> **안전하게 드리프트중입니다. 100%**
>
> 좋은 소식은 감지기가 멀쩡하다는 겁니다. 나쁜 소식은 잡아낼 게 있었다는 겁니다.

AI Safe Driver는 에이전트가 같은 실수를 되풀이할 때 대화를 수습하는 스킬입니다. 직접 호출할 수도 있습니다. 로컬에서 동작하는 결정 규칙 훅은 사용자가 정정한 뒤 에이전트가 잘못을 인정하거나 수정을 약속했는데도 같은 불만이 다시 나오면 스킬을 깨웁니다. 훅이 보내는 신호는 대화를 살펴볼 단서이지, 그 자체로 최종 진단은 아닙니다.

결정 규칙은 낯선 표현을 놓칠 수 있습니다. 그럴 때는 스킬을 직접 실행하면 됩니다. 화가 났다는 이유만으로 드리프트라고 판단하지 않습니다. 관찰된 반복 툴 실패도 명시적 진단 요청이 있을 때만 신호로 다룹니다. 임시 상태에는 범주·횟수·시각만 짧게 보관하며 대화 원문은 저장하지 않습니다.

## 지원 언어

자동 발화 감지는 한국어, 영어, 간체 중국어, 번체 중국어, 일본어를 지원합니다. 직접 호출은 호스트 모델이 이해하는 다른 언어로도 할 수 있습니다.

- 한국어: `왜 같은 실수를 계속 반복해?`
- 영어: `Why do you keep making the same mistake?`
- 간체 중국어: `我说了多少遍了，怎么还是没改？`
- 번체 중국어: `我都說過多少次了，怎麼還是錯的？`
- 일본어: `何回同じことを言わせるの？`

예문을 그대로 외워서 쓸 필요는 없습니다. 각 언어에서 여러 불만 표현을 감지하며, `다시 설명해줘`처럼 평범하게 반복을 요청하는 말은 드리프트로 보지 않습니다.

계기판은 일부러 조금 우스꽝스럽게 만들었습니다. 상태를 물어보면 `안전하게 드리프트중입니다. 0%`나 `안전하게 드리프트중입니다. 100%`처럼 답합니다. 평소 답변에는 붙지 않습니다. 이 숫자는 관찰된 실패를 규칙에 따라 나눈 등급이지, 모델의 가중치나 어텐션을 읽어서 계산한 실제 수치가 아닙니다.

75%나 100%가 나오면 `카운터 스티어링 하시겠습니까?`라고 묻습니다. 계속 실패하던 방식을 멈추고, 범위를 좁힌 복구 방법 하나를 제안하겠다는 뜻입니다. 여기서 "네"라고 답해도 파일 작성, 툴 재시도, 컴팩션, 초기화까지 허락한 것은 아닙니다. 상태를 바꾸는 작업은 하나씩 따로 물어봅니다.

Claude Code와 Codex는 같은 스킬을 씁니다. 대화 복구용 훅과 핸드오버용 훅도 들어 있습니다. 복구용 훅은 툴 재시도, 프로젝트 파일 작성, 핸드오버 작성·준비, 컴팩션, 초기화를 하지 않습니다. 핸드오버용 훅은 `/compact`나 `/clear` 뒤에 실행되지만, 사용자가 미리 승인하고 준비한 핸드오버만 불러옵니다. 실행형 설치 프로그램, MCP 서버, 네트워크 코드, 자동 업데이트 기능은 없습니다.

## 설치

### Claude Code

```text
/plugin marketplace add ssauma/ai-safe-driver
/plugin install ai-safe-driver@ai-safe-driver
```

`/ai-safe-driver:ai-safe-driver`로 직접 실행해도 되고, 같은 실수나 툴 실패가 반복되거나 정정한 내용과 출력 형식을 계속 무시한다고 평소 말투로 이야기해도 됩니다.

### Codex

```bash
codex plugin marketplace add ssauma/ai-safe-driver
codex plugin add ai-safe-driver@ai-safe-driver
```

새 Codex 세션에서 `$ai-safe-driver`를 실행하면 됩니다. 반복되는 문제를 평소 말투로 설명해도 알아듣습니다.

## 대화를 살피는 자동 훅

복구용 훅은 좁고 눈에 보이는 순서만 찾습니다. 사용자가 정정하고, 에이전트가 인정하거나 고치겠다고 약속한 뒤, 같은 불만이 다시 나오는 경우입니다. 사용자가 대화 상태를 명시적으로 물었거나 반복된 툴 실패를 진단해 달라고 분명히 요청한 경우에도 스킬을 깨울 수 있습니다. 툴 오류 하나만으로는 진단을 시작하지 않습니다. 대문자, 욕설, 문장부호, 같은 글자 반복, 화난 말투만으로 등급을 올리지도 않습니다.

훅이 스킬을 깨워도 범주는 단서일 뿐입니다. 스킬은 눈에 보이는 대화에서 실제 불일치를 다시 확인해야 하며, 반복 근거가 없다면 위험을 부풀리지 않고 평소 작업을 이어갑니다. 훅은 최종 드리프트 수치를 계산하지 않으며 상태를 바꾸는 작업의 허락도 대신하지 않습니다.

## 이렇게 말하면 됩니다

예를 들면 다음과 같습니다.

- `왜 같은 실수를 반복해?`
- `또 내 말을 무시했잖아.`
- `변명하지 말고 원인을 말해.`
- `똑같은 툴 호출을 또 했네.`
- `출력 형식을 또 틀렸잖아.`
- `클로드 세션이 길어지니까 출력 형식을 계속 못 맞추네.`
- `지금 드리프트 난 거야?`
- `정상이냐?`
- `드리프트냐?`
- `지금 상태 어때?`
- `새 세션을 파야 해?`

## 무엇이 달라지나

- 같은 실패가 이어지면 조건도 바꾸지 않은 채 다시 시도하는 일을 멈춥니다.
- 확인된 사실, 근거가 있는 원인, 아직 가설인 내용, 모르는 점을 서로 섞지 않습니다.
- 오래된 가정은 버리고 사용자의 마지막 지시부터 다시 확인합니다.
- 다시 시도하기 전에 툴 사용 조건이나 정확한 출력 형식을 점검합니다.
- 현재 세션에서 수습할 수 있으면 그대로 이어갑니다.
- 컴팩션이 도움이 되는지, 소용없는지, 잘못된 맥락까지 남길 위험이 있는지 설명합니다.
- 컴팩션이나 새 세션이 정말 필요할 때만 짧은 핸드오버를 제안합니다.
- 사용자가 미리 허락한 경우에만 `/compact`나 `/clear` 뒤에 핸드오버를 다시 불러옵니다.

겉으로는 자조적인 블랙코미디지만 수습 방식은 진지합니다. 사용자의 마지막 지시로 돌아가 실제로 실패한 내용을 기록하고, 대화 문제와 툴·환경 문제를 나눠 봅니다. 한 번에 한 조건만 바꾸고 결과를 확인하며, 같은 재시도를 끝없이 반복하지 않습니다. 세션을 바꿔야 한다면 다음 대화가 바로 이어받을 수 있도록 핸드오버를 남깁니다.

## 요청할 때만 하는 드리프트 점검

현재 대화가 드리프트 중인지 물어보면, 눈에 보이는 실패를 기준으로 0%·25%·50%·75%·100% 중 하나를 고릅니다. 숫자를 보여주기 전에 무엇이 계속 잘못되는지, 지금 세션에서 수습할 수 있는지, 컴팩션이 도움이 되는지, 새 세션이 필요한지를 설명합니다. 평소 답변에는 상태 문구를 붙이지 않습니다.

75%나 100%라면 계기판 바로 다음 줄에서 카운터 스티어링 여부를 묻습니다. 위험도가 낮을 때는 농담만 하려고 이 질문을 덧붙이지 않습니다.

목표와 출력 형식은 분명한데 대화가 너무 길고 같은 내용이 쌓였다면 컴팩션이 도움이 될 수 있습니다. 그전에 핸드오버에 요구 형식, 필수 키, 금지 사항, 올바른 예시 하나를 적어 둡니다. 인증, 권한, 네트워크, 잘못된 툴 인자, 빠진 사실은 컴팩션으로 고칠 수 없습니다. 요약에 오래된 가정이 남거나 사용자의 마지막 정정이 빠지면 상황이 더 나빠질 수도 있습니다.

## 허락받은 뒤에만 쓰는 핸드오버

진단만 할 때는 아무것도 쓰거나 바꾸지 않습니다. 위험도가 높아도 곧바로 파일을 만들지 않고 다음 두 가지를 따로 물어봅니다.

1. `.ai-safe-driver/handover.md`를 새로 만들거나 덮어써도 되는지
2. `compact` 또는 `clear` 중 어느 전환을 일회성으로 준비해도 되는지

플러그인을 설치했거나 훅을 신뢰했다고 해서 위 작업까지 허락한 것으로 보지 않습니다. `/compact`와 `/clear`도 사용자가 직접 입력해야 합니다. 플러그인이 대신 실행하지 않습니다. `/compact`는 현재 대화를 요약한 뒤 이어가고, `/clear`는 새 대화를 시작합니다. 그래서 `/clear`가 더 큰 변경이라는 점을 먼저 설명합니다.

파일 작성에는 별도 승인이 필요하고, `/compact`나 `/clear` 전환에도 별도 승인이 필요합니다. 플러그인은 `/compact`나 `/clear`를 자동으로 실행하지 않습니다.

`SessionStart` 훅은 일회성 승인 한 번에 한 번만 작동합니다. 짧은 시간 동안 유효한 승인 기록이 있고, 전환 종류와 핸드오버 체크섬까지 모두 맞아야 문서를 다시 읽습니다. 읽은 뒤에는 승인 기록만 지우고 핸드오버 파일은 확인할 수 있게 남겨 둡니다. 유효한 승인이 없으면 아무것도 바꾸지 않습니다. Claude Code와 Codex는 이런 외부 플러그인 훅을 실행하기 전에 내용을 검토하고 신뢰할지 물을 수 있습니다.
