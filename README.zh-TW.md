# AI Safe Driver

[English](README.md) | [한국어](README.ko.md) | [简体中文](README.zh-CN.md) | 繁體中文 | [日本語](README.ja.md)

> **正在安全甩尾。100%**
>
> 好消息：偵測器運作正常。壞消息：還真的有東西可抓。

AI Safe Driver 用來處理 AI 代理程式反覆犯同一個錯誤的對話。你可以直接呼叫這個技能。本機依照固定規則運作的 Hook 會留意一段明確的過程：使用者先提出修正，AI 代理程式承認錯誤或答應修復，之後同類抱怨又出現。Hook 只提醒技能檢查眼前的對話，不會直接下結論。

片語規則可能漏掉陌生說法，因此隨時都能直接執行技能。生氣不代表發生了漂移。觀察到工具反覆失敗後，也只有收到明確的診斷要求才會把它當成訊號。暫存狀態只記錄短期類別、次數和時間戳記，不會儲存對話原文。

## 支援語言

自動語句偵測支援韓文、英文、簡體中文、繁體中文、日文。直接呼叫時，也可以使用執行這項技能的模型能理解的其他語言。

- 韓文：`왜 같은 실수를 계속 반복해?`
- 英文：`Why do you keep making the same mistake?`
- 簡體中文：`我说了多少遍了，怎么还是没改？`
- 繁體中文：`我都說過多少次了，怎麼還是錯的？`
- 日文：`何回同じことを言わせるの？`

這些句子不是口令，不必逐字照念。Hook 能辨識各語言中的多種抱怨方式，但「請再解釋一次」這類一般的重複要求不會算成漂移。

儀表板刻意帶點自嘲，但風險為零時不會聲稱正在漂移。你主動詢問對話狀態時，技能可能顯示 `No current signs of drift.` 或 `Drifting safely. 100%`。一般回覆不會附上這行文字。百分比是依照可見失敗模式得出的規則等級，不是對模型權重、注意力或某種內部漂移數值的測量。

結果是 75% 或 100% 時，技能會問 `Would you like me to countersteer?`。這裡的「反打方向盤」是指停止目前一直失敗的做法，再提出一個範圍明確的復原方案。回答同意只表示願意討論方案，不代表授權外掛程式寫入檔案、重試工具、壓縮對話或清除工作階段。每項狀態變更都必須另外確認。

Claude Code 和 Codex 使用同一份技能。外掛程式也包含對話復原 Hook 和交接 Hook。復原 Hook 不會重試工具、寫入專案檔案、建立或啟用交接文件，也不會壓縮或清除工作階段。交接 Hook 會在 `/compact` 或 `/clear` 後執行，但只會載入你事先核准並準備好的交接內容。外掛程式不含可執行安裝程式、MCP 伺服器、連網程式碼或自動更新檢查。

## 安裝

### Claude Code

```text
/plugin marketplace add ssauma/ai-safe-driver
/plugin install ai-safe-driver@ai-safe-driver
```

執行 `/ai-safe-driver:ai-safe-driver`，或直接說明發生了什麼，例如同一個錯誤或工具呼叫不斷失敗、修正被忽略、輸出格式一再出錯。

### Codex

```bash
codex plugin marketplace add ssauma/ai-safe-driver
codex plugin add ai-safe-driver@ai-safe-driver
```

可以直接執行 `$ai-safe-driver`。也可以用自己的話描述反覆發生的問題。在新的工作階段中，請簡述反覆發生的失敗或提供已核准的交接檔案；此技能無法讀取不可見的先前對話。

## 自動復原 Hook

自動鉤子需要 Node.js 20 或更新版本。

復原 Hook 只檢查範圍很窄、可以直接觀察的順序：使用者提出修正，AI 代理程式承認錯誤或承諾修復，之後同類抱怨再次出現。明確的對話健康檢查，或明確要求診斷反覆失敗的工具呼叫，也能喚醒技能。單次原始工具錯誤還不夠。大寫、髒話、標點、重複字元和憤怒語氣本身都不會提高等級。

Hook 喚醒技能時，所附類別只是一條線索。技能必須回到目前看得到的對話，重新確認實際偏差。如果沒有反覆發生的證據，就不會誇大風險，而是繼續正常工作。Hook 不計算最終漂移百分比，也不會代替使用者核准任何狀態變更。

## 可以這樣說

- `為什麼一直犯同一個錯誤？`
- `我剛剛才修正過，你怎麼又忽略了？`
- `別急著道歉，先告訴我真正原因。`
- `同一個失敗的工具呼叫又執行了一次。`
- `輸出格式怎麼又錯了？`
- `工作階段變長以後，你一直守不住指定格式。`
- `對話是不是跑偏了？`
- `現在的工作階段狀態正常嗎？`
- `要不要開一個新的工作階段？`

## 它會做什麼

- 同類失敗反覆出現時，停止原樣重試。
- 分開記錄已確認事實、有依據的原因、待驗證假設和未知事項。
- 回到使用者最新指示，不再沿用已經失效的舊假設。
- 再次操作前，先核對工具條件或精確的輸出格式。
- 如果目前工作階段可以可靠復原，就留在原處繼續。
- 說明壓縮上下文是否有幫助、是否無效，或是否可能保留錯誤前提。
- 只有確實需要壓縮或新工作階段時，才建議製作簡短交接文件。
- 只有事先獲得核准，才會在 `/compact` 或 `/clear` 後重新載入交接內容。

外表是自嘲式黑色幽默，但復原流程採用嚴謹的事故應變方式：回到最新指示，記錄實際失敗，把對話問題和工具或環境問題分開，每次只改變一個條件，接著驗證結果並限制重試次數。如果必須更換工作階段，就留下足夠讓下一次接手的交接內容。

## 隨選漂移檢查

你詢問對話是否漂移時，技能會依照可見失敗模式選擇 0%、25%、50%、75% 或 100%。顯示數字前，它會先說明問題為何持續、目前工作階段能否復原、壓縮是否有用，以及是否應該開始新的工作階段。一般回覆不會顯示狀態列。

結果是 75% 或 100% 時，儀表板下一行會詢問是否要反打方向盤。風險較低時，不會只為了湊笑話而多問一句。

當目標和輸出要求仍然清楚，只是對話過長而且內容重複時，壓縮可能有幫助。技能會先在交接內容中固定輸出格式、必填欄位、禁止事項和一個正確範例。身分驗證、權限、網路、錯誤的工具參數或缺少事實，無法靠壓縮解決。如果摘要保留舊假設，或漏掉使用者最近的修正，壓縮反而可能讓問題更嚴重。

## 取得許可後才會交接

診斷階段是唯讀的。即使風險很高，技能也不會立刻寫入檔案，而是分別詢問：

1. 是否可以建立或覆寫 `.ai-safe-driver/handover.md`
2. 是否可以只為 `compact` 或 `clear` 其中一種切換做一次性準備

安裝外掛程式或信任 Hook 不代表同意上述操作。`/compact` 和 `/clear` 仍由你親自輸入，外掛程式不會代為執行。`/compact` 會摘要目前對話後繼續，`/clear` 會開始新的對話，因此後者被視為較大的變更。

寫入檔案需要另行核准，準備 `/compact` 或 `/clear` 切換也需要另行核准。外掛程式不會自動執行 `/compact` 或 `/clear`。

如果 Git worktree 尚未忽略 `.ai-safe-driver/`，準備交接時還需要把這一行加入該 worktree 的本機 Git 排除檔。技能會先顯示確切路徑，並在寫入前取得許可。它不會修改共用的 `.gitignore` 或 Git 設定。

內建的 `SessionStart` Hook 會消耗一次性核准。只有短期核准紀錄仍然有效，而且切換類型與交接檔案的 SHA-256 雜湊值都一致時，它才會載入交接內容。載入後只刪除核准紀錄，交接檔案會留下供你檢查。沒有有效核准時，Hook 不會做任何變更並靜默結束。Claude Code 和 Codex 也可能要求你先檢查並信任這個第三方 Hook。
